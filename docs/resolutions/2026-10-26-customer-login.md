# Migrated customer credentials, email-code login and password reset — 26 October 2026

The private osTicket export contains17 customer account password hashes:14 confirmed and3 pending activation (osTicket1.14.3 CONFIRMED=1, LOCKED=2, REQUIRE_PASSWD_RESET=4, per official include/class.user.php). Contacts without a source account have no recoverable password. Passwords are never decrypted or emailed. Only confirmed, unlocked source accounts with supported bcrypt hashes may populate an unchanged invited imported customer with no current password/login. Existing staff, current passwords and activated users are preserved. Import is dry-run by default, tenant/source-ID bound, conditional and repeat safe; it logs aggregate counts only. Private input/backups remain outside Git.

Customer password sign-in accepts registered email or a mapped osTicket username. Compatibility is restricted to imported customer bcrypt hashes (bounded format/cost), and a successful login atomically upgrades the stored hash to Argon2id. There is no old-password fallback after reset. Ambiguous identities fail closed.

A separate customer email-code sign-in option works without forcing a password change. Ten-minute codes are purpose-bound HMACs, expire, work once and allow five guesses. Atomic issue/claim bounds concurrent sends/logins; resend is limited to one per ten minutes. Requests have the same UI answer for missing/ineligible accounts and use existing CAPTCHA when configured. Staff, suspended/deleted users and suspended tenants cannot use this customer route. Existing invited imported customers activate only after proving their registered mailbox. No source staff identity or permission is imported.

Forgot password also serves still-invited imported customers: a single-use reset link sets a new policy-compliant password and activates that customer. Active customers retain the existing reset flow. Reset invalidates old sessions, outstanding OTP/activation challenges and other reset links. Existing normal staff password/Entra routes remain.

Validation:405 unit tests, workspace types/lint, and isolated Docker integration with synthetic records and no SMTP worker. Integration exercises legacy email/username login and rehash, incorrect passwords, OTP concurrent issue/use, expiry/guess/replay denial, passwordless invited activation, reset of active/invited accounts, old-password/session/code invalidation and staff/suspension boundaries. Production import counts, runtime/CI and browser evidence will be recorded after release. Real customer mailbox receipt is not claimed from an outbox test.
