# Worktello interactive manual

Open `index.html` in a browser. For the full portable package, extract `outputs/manual/Worktello-Manual-2026-10-25.zip` and open START-HERE.html; the package preserves linked technical records too. No install, external fonts, CDN or application secrets are required. Keep this folder together when copying it; screenshots and styles use relative paths. Live application links use the existing HTTPS production hostname and require the reader's own account.

- `index.html`: accessible navigation and reading shell.
- `manual.css`: desktop/mobile/print layout.
- `content.json`: editable plain-language chapters, role tags, source references and resolution summaries.
- `content.js`: generated offline mirror of content.json; regenerated by scripts/package-manual.py so file:// reading needs no network fetch.
- `manual.js`: search, chapter navigation, local step checklists, screenshot zoom and printing.
- `assets/`: actual application screenshots and approved brand artwork. `assets/manifest.json` records their origin/date and whether the screen is production or isolated QA. No mock screenshot is labelled live.
- `downloads/`: non-sensitive blank CSV templates only; never put exports of customer/business records here.
- `../resolutions/`: organized technical diagnosis/fix/verification records. `../OUTLOOK-WEB.md` remains a compatibility link/source record.

Checklists are stored only in this browser's local storage. They are reading progress, not task completion. This manual does not send emails, create tasks, import CSV files or modify application settings. A screenshot verifies appearance, not every action described in a chapter. Evidence labels distinguish screen checks, prior service/database tests and untested device/write flows.

## Updating after each resolution

1. Add a dated Markdown record using `../resolutions/TEMPLATE.md`: symptom, evidence, cause, scoped fix, tests, deployment, live acceptance, limitations, rollback and source/PR.
2. Capture the actual UI with synthetic/blank/filtered records where possible. Exclude credentials, tokens, emails, customer documents and confidential business content. Keep the original screenshot; use HTML callouts/captions rather than fabricated UI.
3. Copy screenshots into assets, add capture metadata and update the relevant `content.json` chapter and resolution card. Keep deployment facts out of general user steps.
4. Check search, keyboard focus, mobile layout, image zoom, relative links and print view in a browser. Verify all local assets exist.
5. Commit/push the manual with the resolution record, preserving unrelated work. Publication to a public application route is a separate action; this manual is a local/repository artifact.

## Local preview and portable package

From the repository root:

```sh
python3 scripts/serve-manual.py
python3 scripts/package-manual.py
```

Preview: http://localhost:3188/docs/manual/ . The preview binds only to 127.0.0.1, disables directory listings and serves only handbook assets/referenced Markdown; environment/Git/private source paths are rejected. Stop the preview with Ctrl+C. The ZIP is generated under outputs/manual and contains an integrity manifest, handbook assets and selected linked documentation; it does not include app environments, database backups or business exports.

When updating, advance the version/date in content.json, refresh screenshot provenance and run the packaging script again. QA.md records actual checks and device/print limits; do not replace these with assumed passes.

## Screenshot policy (owner preference)

Keep the manual text-first. Use a screenshot only when it resolves a complex visual decision: timeline manipulation, CSV transfer rules or integration troubleshooting. Current guide has three selected figures across 27 chapters. Do not add screenshots to simple sign-in/navigation/forms. Keep additional safe captures under assets/archive as evidence, not inline reading content; provenance remains in assets/manifest.json.
